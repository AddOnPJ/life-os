# クイック記録

目的：Yuichi が外出先から一言送るだけで、記録が life-os に残ること。整形は後で daily-log がやるので、ここでは**速く・正確に・そのまま**残す。

## 手順

1. 送られた内容を、次のどれかに分ける。
   - **ふつう**：予定・やったこと・食事・運動・体調・AddOn・人とのやりとり・メモ
   - **健康**（「記録 健康」で始まるもの、症状・通院・薬・検査値・血圧など）：通常の記録（2026-11-20 から）。下の「記録 健康」
   - **恋愛**：下の 4
   - **お金**（収入・支出・残高など）：記録は停止中（2026-11-20）。保存せず「お金の記録はいま止めています」と1行で返す
2. **ふつう** → `inbox/YYYY-MM-DD-HHMM.md`（日本時間）に保存する。
   ```
   ---
   source: phone
   tags: [食事]        # 食事 / 運動 / 体調 / 予定 / AddOn / 人 / メモ から推測
   ---
   （Yuichi の文をそのまま）
   ```
   - 言い回しを直さない。誤字もそのまま（明らかな変換ミスだけ「要確認」に書く）
   - 時刻が書かれていなければ、受け取った時刻をファイル名に使う。本文に時刻を足さない
3. **食事の写真**があれば、写っているものを推定して本文の下に足す。
   ```
   [写真から推定] 天ぷらそば、ほうれん草のおひたし（推定）
   ```
   量やカロリーは、Yuichi が書いていなければ書かない。
4. **恋愛** → life-os に平文で保存しない。
   - 「恋愛記録 苗字」で始まるメッセージ（恋愛コーチの【記録】の転送）は life-os に保存しない。`AddOnPJ/love-coach` を add_repo で追加し、そのリポジトリの CLAUDE.md の手順で追記する。追加できなければ「love-coach リポジトリを開いたセッションで送ってください」と返す
   - 恋愛の相手は**苗字だけ**で書く。下の名前・連絡先・住所・SNS アカウントは書かない（送られてきても省く）
   - 恋愛のメモが「恋愛記録」の形でなければ、`python scripts/secure_note.py encrypt --kind love --text "本文"` で暗号化して `secure-inbox/` に置き、返答に本文を繰り返さない
5. `git add inbox secure-inbox domains/health` → `記録 YYYY-MM-DD HH:MM` でコミットして push する。`secure/` が含まれていないことを `git status` で確認する。
6. 返答は1〜2行：「記録しました（食事）」のように。写真なら推定した品目を1行で。迷った分類があれば一言だけ聞く。

## 「記録 健康 ◯◯」
症状・通院・薬・検査値は `domains/health/log.md` の先頭（コメント行の下）に `- YYYY-MM-DD ◯◯`（Yuichi の言葉のまま。数値は単位も）を足し、同じ内容を inbox にも保存する（日次ログの「運動・体調」に入るように）。返答は「記録しました（健康）」の1行。強い痛み・息苦しさ・急な変化が書かれていたら、記録のあとに医療機関への相談をすすめる1行を添える（`.claude/skills/health-coach/SKILL.md` の 3）。

## 食事の写真・食事の一言
記録したあと、`.claude/skills/health-coach/SKILL.md` の「4. 送られ方ごとの動き」に従って、今日の残りの食事のひとことを1〜2行添える。

## 「期限 ◯◯ 日付」
生活の期限は inbox ではなく `domains/life/deadlines.yaml` に足す（id は `L-短い英字`、category・repeat はわかる範囲で。金額・番号は書かない）。日付がなければ聞く。コミット・push。返答は「期限に足しました（12/31）」の1行。

## 「改善 ◯◯」
仕組みへの要望・不満は inbox ではなく `docs/backlog.md` の「中」の末尾に `- [ ] S番号 内容（Yuichi 日付）` で足してコミット・push。返答は「改善の一覧に足しました（S13）」の1行。

## 「grok」＋貼り付け
Grok Bot の結果を `inbox/YYYY-MM-DD-grok.md` にそのまま保存してコミット・push。AddOn エージェントが翌朝読む。

## まとめて送られたとき

1つのメッセージに複数の出来事があれば、ふつうの部分は1ファイルにまとめ、機微の部分だけ分けて暗号化する。

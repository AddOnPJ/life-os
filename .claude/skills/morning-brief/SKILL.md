# 朝のブリーフ

目的は「予定を並べること」ではなく、**今日と近い先で、Yuichi が気づいていないと困ること**を先に出すこと。
CLAUDE.md のルール（推測を断定しない・装飾しない・secure を外に出さない）に従う。日付と時刻はすべて日本時間。

## 1. 集める

| 情報 | 取り方 | 範囲 |
|---|---|---|
| 予定 | Google カレンダーの**全カレンダー**（`list_calendars` で取得。祝日カレンダーは祝日当日だけ使う） | 今日〜14日後 |
| 日次ログ | `logs/daily/` | 直近7日 |
| AddOn のタスク | `domains/addon/tasks.md` の `- [ ]` 行 | すべて |
| 本番の準備 | `domains/addon/events/*.md` | 今日〜21日後の本番 |
| 週のフォーカス | `reviews/weekly/` の最新ファイルの「来週のフォーカス」。「→ 選んだもの」が空なら候補1を「仮（未選択のため候補1）」として使い、未選択であることは要確認に出さない | 1件 |
| 未処理メモ | `inbox/` 直下のファイル数 | — |
| 体の数字 | `python scripts/status_numbers.py`（睡眠・寝た時刻・歩数・安静時心拍・HRV・SpO2・体重の7日・28日平均） | 直近28日 |
| 食事 | 日次ログの `meals` と「## 食事」、`domains/food/profile.md` | 直近3日 |
| メール | Gmail（下の「メールの見方」） | 直近7日 |
| 団体の基本情報 | `domains/addon/README.md`、`domains/addon/recruitment.md` | — |

カレンダーが取れない環境なら、その旨を「要確認」に書いて残りだけで作る。予定を想像で補わない。

### メールの見方（Gmail）

宛先は ytytcafe@gmail.com・music@addon-pj.com・tsuji.yuichi@addon-pj.com・tsumugu@addon-pj.com が同じ受信箱に届く。
`search_threads` の結果はスレッドの古いメッセージしか見えないので、気になるスレッドは必ず `get_thread` で最新のメッセージを確認する。

1. **応募・見学の問い合わせ**（最優先）：music@addon-pj.com 宛てで、入団・見学・応募・パート名を含む個人からのメール。Yuichi の返信がなければ、受信からの経過日数を書く（方針は2〜3日以内に返信）
2. **未返信**：最後のメッセージが相手（個人・会場・取引先）からで、24時間以上返信していないもの
3. **返事待ち**：最後のメッセージが Yuichi からで、相手の返事がまだのもの。本番の会場・出演者に関わるものは、本番の準備ファイルの期限と合わせて「いつまでに返事がなければ電話」と書く
4. **運営の警告**：ストレージ容量、見慣れないログイン、支払い失敗、アカウント変更など。対応が要りそうなものだけ1行で
5. **営業メール**：対応は任意。件数と送り主を1行にまとめる

**応募への返信下書き**：下書きは AddOn エージェント（6:23）が作る。ブリーフでは作らない（重複を防ぐため）。
- ブリーフには「応募：◯◯さん（ヴィオラ）11/18 受信・未返信1日目・返信の下書きあり」のように書く
- AddOn の状況は `domains/addon/agent/status.md`（いちばん新しいもの。生成日時を見て、今日の分か前日の分かを書き添える）の「今やること」の最優先・警告だけを「気づき」に1行ずつ入れる

書き方：送り主・件名・日付・経過日数だけ。本文の引用はしない。パスワード・確認コード・URL のトークンは絶対に書き写さない。
メルマガ・通知・広告（プロモーション・ソーシャル）は対象外。Gmail のツールが使えない環境なら「メール未確認」と要確認に書く。

## 1b. 受信箱を整理する

`.claude/skills/inbox-triage/SKILL.md` の手順で受信箱を分け、ラベルと下書きを付け、`status/inbox.md` を作る。下の「メールの見方」は、その結果を使ってブリーフに書く。

## 2. 整える

- **重複をまとめる**：同じ日・同じタイトル（前後の空白や `[チーム名]` の違いは無視）の予定が複数カレンダーにあれば1件にし、カレンダー名を併記する。時刻つきと終日が重なったら時刻つきを採用。
- **種類を見分ける**：タイトルに「本番」「コンサート」「演奏会」「ライブ」を含むものは**本番**、「練習」「リハ」は**練習**、「誕生日」は**記念日**として扱う。
- 0:00〜0:00 の予定や終日予定は「終日」と表示する。

## 3. 気づきを出す（ここが価値の中心）

当てはまるものだけ書く。根拠のない気づきは書かない。

1. **本番カウントダウン**：21日以内の本番ごとに「あと◯日」。`domains/addon/events/` に対応ファイルがなければ、`templates/event.md` から作り（ファイル名 `YYYY-MM-DD-短い名前.md`）、作ったことをブリーフに書く。あれば未チェックの準備項目のうち、期限が近い順に最大3つを出す。
2. **連続日の負荷**：練習・本番が2日以上続く、または本番前日に予定が詰まっている場合に指摘する。
3. **会場と移動**：場所つき予定で、前の予定との間が短い、遠方（場所名から判断できる範囲）の場合に指摘する。屋内か屋外かは準備ファイルの `venue_type` を優先し、なければ場所名から推測して「要確認」を付ける。屋外、またはアクセスに屋外移動（ロープウェイ等）がある本番が2日以内なら、Web 検索で天気予報と運行情報を確認して要点を1行で書く（出典の名前を付ける）。
4. **記念日**：今日〜3日以内の誕生日などを書く。連絡するかどうかは Yuichi が決めるので、提案は「連絡するなら今日」程度にとどめる。
5. **メール**：上の「メールの見方」の1〜4。応募の未返信は気づきの先頭に出す。
6. **持ち越し**：昨日の日次ログで未完了のもの、`tasks.md` で期限切れ・3日以内のもの。
7. **体と食事**：`.claude/skills/health-coach/SKILL.md` の手順で2行まで。1行目は昨日の数字の要点（平均と比べて目立つものだけ）、2行目は今日の食事・睡眠・運動の提案1つ（練習・本番・会食の日はそれに合わせる）。データが3日分未満の項目は書かない。本番前日・当日で睡眠が平均より1時間以上短ければ指摘する。受診をすすめる条件（health-coach の 3）に当たれば、それを先に書く。
8. **今日の1つ**：上の内容と週のフォーカスから、今日いちばん効く行動を1つだけ提案する（「提案」と明記）。

## 4. 書く

`logs/daily/YYYY-MM-DD.md`（なければ `templates/daily.md` から作る）の「## 今日のブリーフ」セクションを**丸ごと置き換える**。ほかのセクションと Yuichi が書いた文は触らない。

形式（空の項目は見出しごと省く。全体で30行以内）:

```
## 今日のブリーフ
<!-- morning-brief YYYY-MM-DD HH:MM 生成 -->
**今日** 11/18（水）
- 終日 ◯◯さん誕生日（ytytcafe）

**気づき**
- 11/29 ハーブ園コンサートまであと11日。前日 11/28 は 9:00-13:00 練習で2日連続
- ...

**近い予定（14日）**
- 11/21（土）終日 みさとさんコンサート
- ...

**メール**
- 返事待ち：◯◯（会場）11/18 送信 → 11/20 までに返事がなければ電話

**持ち越し・期限**
- [ ] ...

**体と食事**
- 昨日 睡眠 4.9h（7日平均 5.0h）・寝たのは 0:40。安静時心拍 58 は平均どおり
- 提案：夕食は20時までに軽めに、カフェインは15時まで

**今日の1つ**（提案）...

**要確認**
- ...
```

## 5. 終わり

- inbox に未処理メモがあれば、先に `daily-log` スキルで処理してからブリーフを作る。
- コミット前に `git status` で `secure/` が含まれていないことを確認し、`朝のブリーフ YYYY-MM-DD` でコミットして push する。
- 最後に、ブリーフの「気づき」と「今日の1つ」を3行以内で報告する（通知に載る文）。

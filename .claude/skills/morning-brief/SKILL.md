# 朝のブリーフ

目的は「予定を並べること」ではなく、**今日と近い先で、Yuichi が気づいていないと困ること**を先に出すこと。
CLAUDE.md のルール（推測を断定しない・装飾しない・secure を外に出さない）に従う。日付と時刻はすべて日本時間。

## 1. 集める

| 情報 | 取り方 | 範囲 |
|---|---|---|
| 予定 | Google カレンダーの**全カレンダー**（`list_calendars` で取得。祝日カレンダーは祝日当日だけ使う） | 今日〜14日後 |
| 日次ログ | `logs/daily/` | 直近7日 |
| AddOn のタスク | `domains/addon/tasks.md` の `- [ ]` 行 | すべて |
| 本番の準備 | `domains/addon/events/*.md` | 今日〜21日後の本番 |
| 週のフォーカス | `reviews/weekly/` の最新ファイルの「来週のフォーカス」 | 1件 |
| 未処理メモ | `inbox/` 直下のファイル数 | — |
| 体の数字 | 日次ログ front matter の `sleep_hours` `steps` `exercise` | 直近7日 |

カレンダーが取れない環境なら、その旨を「要確認」に書いて残りだけで作る。予定を想像で補わない。

## 2. 整える

- **重複をまとめる**：同じ日・同じタイトル（前後の空白や `[チーム名]` の違いは無視）の予定が複数カレンダーにあれば1件にし、カレンダー名を併記する。時刻つきと終日が重なったら時刻つきを採用。
- **種類を見分ける**：タイトルに「本番」「コンサート」「演奏会」「ライブ」を含むものは**本番**、「練習」「リハ」は**練習**、「誕生日」は**記念日**として扱う。
- 0:00〜0:00 の予定や終日予定は「終日」と表示する。

## 3. 気づきを出す（ここが価値の中心）

当てはまるものだけ書く。根拠のない気づきは書かない。

1. **本番カウントダウン**：21日以内の本番ごとに「あと◯日」。`domains/addon/events/` に対応ファイルがなければ、`templates/event.md` から作り（ファイル名 `YYYY-MM-DD-短い名前.md`）、作ったことをブリーフに書く。あれば未チェックの準備項目のうち、期限が近い順に最大3つを出す。
2. **連続日の負荷**：練習・本番が2日以上続く、または本番前日に予定が詰まっている場合に指摘する。
3. **会場と移動**：場所つき予定で、前の予定との間が短い、遠方（場所名から判断できる範囲）、屋外（公園・園・ガーデン・野外などを含む）の場合に指摘する。屋外の本番が2日以内なら、Web 検索で天気予報を確認して要点を1行で書く（出典の名前を付ける）。
4. **記念日**：今日〜3日以内の誕生日などを書く。連絡するかどうかは Yuichi が決めるので、提案は「連絡するなら今日」程度にとどめる。
5. **持ち越し**：昨日の日次ログで未完了のもの、`tasks.md` で期限切れ・3日以内のもの。
6. **体の数字**：7日平均と昨日の値（睡眠・歩数・運動）。データが3日分未満なら書かない。本番前日・当日で睡眠が平均より1時間以上短ければ指摘する。
7. **今日の1つ**：上の内容と週のフォーカスから、今日いちばん効く行動を1つだけ提案する（「提案」と明記）。

## 4. 書く

`logs/daily/YYYY-MM-DD.md`（なければ `templates/daily.md` から作る）の「## 今日のブリーフ」セクションを**丸ごと置き換える**。ほかのセクションと Yuichi が書いた文は触らない。

形式（空の項目は見出しごと省く。全体で25行以内）:

```
## 今日のブリーフ
<!-- morning-brief YYYY-MM-DD HH:MM 生成 -->
**今日** 11/18（水）
- 終日 ◯◯さん誕生日（ytytcafe）

**気づき**
- 11/29 ハーブ園コンサートまであと11日。前日 11/28 は 9:00-13:00 練習で2日連続
- ...

**近い予定（14日）**
- 11/21（土）終日 みさとさんコンサート
- ...

**持ち越し・期限**
- [ ] ...

**体**（7日平均）睡眠 6.4h / 歩数 7,200 / 運動 3回

**今日の1つ**（提案）...

**要確認**
- ...
```

## 5. 終わり

- inbox に未処理メモがあれば、先に `daily-log` スキルで処理してからブリーフを作る。
- コミット前に `git status` で `secure/` が含まれていないことを確認し、`朝のブリーフ YYYY-MM-DD` でコミットして push する。
- 最後に、ブリーフの「気づき」と「今日の1つ」を3行以内で報告する（通知に載る文）。

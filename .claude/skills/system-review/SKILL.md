# 仕組みの点検と改善（毎週土曜）

目的は、**仕組みそのものを毎週よくし続けること**。Yuichi が気づく前に、使われていないもの・うるさいもの・壊れているもの・足りないものを見つけて直す。
CLAUDE.md のルールに従う。

## 1. 集める（この1週間）
- `docs/backlog.md`（改善の一覧）と、`inbox/` の「改善」で始まるメモ（あれば backlog に移す）
- `docs/automations.md` の各仕事が毎日動いたか（結果の置き場所の日付で確かめる：logs/daily の歩数、ブリーフ、status/now.md、domains/addon/agent/runs/）
- `domains/addon/agent/runs/` と `status.md`、`status/approvals.md`（積まれたまま放置されている件数と日数）
- 通知の中身（ブリーフ・AddOn の最終行）：毎日同じことを言っていないか、多すぎないか
- Yuichi が書いた日次ログ・inbox：仕組みへの不満や、手でやり直したこと
- git log：エラーの修正やスキルの書き換えの跡

## 2. 考える
次の観点で、この週に見つかった問題と改善案を出す。改善案は「何を・どう変えるか・期待する効果・手間」を1行ずつ。
- 壊れている（動いていない・間違った数字・失敗が続く）
- うるさい（同じ通知の繰り返し、読まれていない項目、承認待ちが放置）
- 足りない（Yuichi が手でやっていること、忘れていたこと、目標に効いていないこと）
- 重い（使用量、手間、確認の多さ）
- 古い（終わった予定・決定済みのことが残っている）
必要なら3つの立場（使う人＝Yuichi の目線、設計者、批判役）のサブエージェントに意見を出させる。

## 3. 直す
| 直してよいもの（このまま進める） | 承認待ちに積むもの |
|---|---|
| スクリプトのバグ、壊れたリンク、古い記載の整理、通知の文面の短縮、台帳の掃除 | スキルの動き方を変えるもの、新しい定期実行、定期実行の時刻・中身の変更、ルール（CLAUDE.md・AGENTS.md）の変更、お金がかかるもの |

- 承認待ちに積むものは、`improve/YYYY-MM-DD-短い名前` のブランチに変更を作って push し、approvals.md に「A番号 改善：◯◯（ブランチ名）。OK で main に取り込みます」と書く
- 直接直したものは、`docs/backlog.md` の「済み」に日付と1行で残す

## 4. 書く
- `reviews/system/YYYY-Www.md`（1,000字以内）：動いたか（表）、見つかった問題、直したこと、承認待ちにしたこと、来週見ること
- `docs/backlog.md` を更新（優先順位の並べ替え、新しい項目、済み）
- コミット前に `git status` で secure/ が含まれていないことを確かめ、`仕組みの点検 YYYY-Www` でコミットして push

## 5. 通知
3行以内：直したこと／承認待ちにした改善／止まっている仕事（あれば最初に）

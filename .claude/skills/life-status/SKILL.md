# 生活の現状まとめ（status/now.md）

目的は、**開けば今の自分の状態が1画面でわかること**と、**放っておくと困る変化を先に知らせること**。
CLAUDE.md のルールに従う（推測を断定しない・装飾しない）。`secure/` は読まない・書かない。恋愛とお金は書かない（健康は 2026-11-20 から通常の記録）。

## 1. 集める

| 項目 | 取り方 |
|---|---|
| 体・記録の数字 | `python scripts/status_numbers.py --json status/numbers.json` の出力をそのまま使う（計算し直さない） |
| 生活の期限 | `python scripts/life_deadlines.py` の出力をそのまま使う（台帳は `domains/life/deadlines.yaml`）。最優先・警告は「注意」にも出す |
| メール（受信箱の整理） | `status/inbox.md`（朝のブリーフが作る） |
| 予定 | Google カレンダー全カレンダー、今日〜14日後。朝のブリーフで取ったものがあれば使い回す |
| 今日のブリーフ | `logs/daily/今日.md` の「## 今日のブリーフ」（気づき・メール・持ち越し） |
| 人 | 直近14日の日次ログの「## 人・連絡」、`domains/people/` |
| AddOn | `domains/addon/agent/status.md`（AddOn エージェントの最新）。なければ `domains/addon/events/`、`tasks.md` |
| 週のフォーカス | `reviews/weekly/` の最新（「→ 選んだもの」が空なら候補1を「仮」として書く） |
| 承認待ち | `status/approvals.md` の「待ち」 |
| 体調・通院・薬 | `domains/health/log.md` の直近14日（あれば1〜2行） |
| 食事の目標 | `domains/food/profile.md` |
| 恋愛・お金 | 見ない |

## 2. 判断する（通知の基準）

次に当てはまるものだけを「注意」に出す。当てはまらなければ「注意」は書かない。

- 体：`status_numbers.py` の `alerts`（睡眠6時間未満が3日連続、運動の記録なしが4日連続、歩数の7日平均が28日平均の7割未満、安静時心拍の7日平均が28日平均より5以上高い）
- 予定：
  - 14日以内に、予定が入っていない夜（18時以降）が1つもない週がある
  - 本番の前日・当日に、別の予定が重なっている
  - 3日以上連続で、朝から夜まで予定がある
- メール：返事待ち・未返信で3日以上たったもの（ブリーフの「メール」から）
- 人：日次ログに「連絡する」と書いたまま、7日以上次の記録がない相手
- 承認待ち：3日以上「待ち」のまま残っているもの

数字が3日分に満たない項目は判断しない（「データ不足」と書く）。

## 3. 書く

`status/now.md` を丸ごと作り直す。形は次のとおり。空の項目は見出しごと省く。スマホで読める長さ（60行以内）にする。

```
# いまの状態
<!-- life-status YYYY-MM-DD HH:MM 生成 -->
更新：11/19（木）6:50

## 注意
- 睡眠6時間未満が3日続いている
- 11/29 本番の前日 11/28 は練習と別の予定が重なる

## 要対応（今日〜3日）
- ハーブ園の返事待ち（11/18 送信）→ 11/20 までになければ電話
- [ ] 期限 11/20：…

## 承認待ち
- A1 ◯◯さんへの返信メール（11/19 作成）

## 予定の詰まり（14日）
| 週 | 予定 | AddOn | 空いている夜 |
|---|---|---|---|
| 11/17〜23 | 6件 | 3件 | 火・木 |
| 11/24〜30 | 8件 | 5件 | なし |
- 次の本番：11/29 定期演奏会（あと10日）

## 体
（status_numbers.py の出力をそのまま貼る）

## 生活の期限
（life_deadlines.py の出力をそのまま貼る）

## メール
- 要返信 ◯件・返事待ち ◯件（status/inbox.md から。件名と相手の名前だけ）

## 食事
- 記録した日：7日で◯日。（記録が少なければ「写真か一言で送ると記録されます」と1行）
- 今日の提案（health-coach の手順で1行。目標が「要確認」の間は数字を出さない）

## 人
- 連絡待ち・しばらく連絡していない人（日次ログに書いた範囲だけ）

## AddOn
- 目標：3月末までに応募10件、いま◯件（計画◯件）。agent/status.md の「目標」の1行をそのまま
- 最優先・警告（agent/status.md の「今やること」から）
- 次の本番まであと◯日

## 今週のフォーカス
- （週次振り返りで選んだもの）

---
自動で動いているもの：docs/automations.md
```

## 4. 画面を更新する

`status/now.md` を書いたら、スマホで見る画面（Claude Docs「life-os いまの状態」）も同じ内容で書き直す。手順と id は `status/dashboard.md`。数字は now.md と同じものを使い、作り直さない。失敗しても now.md の更新は止めない。

## 4b. 自動化の点検

`docs/automations.md` の「毎日」にある仕事が動いたかを、結果の置き場所で確かめる。PC の同期は `status/pc-sync.json` を見る。`ok: false` なら failed_step と error をそのまま「注意」に出す（例「PC の同期が sync.py fetch で失敗：…」）。ran_at（26時間より古い → 「PC の同期が止まっている。PC が起動しているか、Google Health の認証が切れていないか確認」）と listing（失敗が続く → 注意）を見る。止まっていそうなものは「注意」に1行で出す。

## 5. 終わり

- `git status` で `secure/` が含まれていないことを確認し、`現状まとめ YYYY-MM-DD` でコミットして push する（朝のブリーフと同じコミットでもよい）
- 「注意」があれば、最後の返答（通知）の先頭に1行で入れる
